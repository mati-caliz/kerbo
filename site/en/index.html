Why

Five tools, five configurations and a server in swap.

A repo with a Java backend, a TypeScript front end and a Python service carries one linter per language today, each with its plugins, its runtime, its report format and its own way of counting the same thing. kerbo is a single native engine that applies the same rules to all of them.

In Python, ruff is already written in Rust and is still faster; there kerbo wins on memory and on being a single tool for everything.

What it does

Rules written once, applied the same way in every language.

01 · one binary

No runtimes, no plugins

No node_modules with ESLint per repo, no tool venvs, no Gradle or Maven plugins. One Rust executable, the same for all your repos.

02 · same bar

Universal rules

File and function length, cyclomatic and cognitive complexity, and parameters: one definition and one threshold across the four languages, magic numbers and short names in all four, nesting in TypeScript and Go, duplicate blocks in all four and commented-out code in Python and Go. And Rust, with clippy's rules.

03 · parity

Same results as what it replaces

Every rule is validated against the original tool on real repos. If it does not flag exactly the same, it does not ship: zero differences on the measured production repos in all four languages, except for two documented limits of the TypeScript parser.

For AI agents

Guardrails for the code Claude Code, Cursor and Copilot write.

Today's linters talk to a person. An agent that writes and fixes in short loops needs something else: to know exactly what to fix, and that nobody lets it "fix" a problem by hiding it.

  • Anti-cheat. Warns when a change dodges a problem instead of fixing it: a new eslint-disable, noqa or @SuppressWarnings, a loosened threshold, a deleted, skipped or emptied test, an any.
  • Output for agents. Short rows grouped by file, prioritized, with how to fix each rule stated once: up to 3.7 times fewer tokens than JSON.
  • Claude Code hook. Reviews every file the agent edits, in milliseconds, and hands back what it found so the agent fixes it in the same turn.
  • Stable identifiers and kerbo explain. On the next turn the agent knows what it fixed, what is left and how to fix each rule.
  • MCP server for Claude Code, Cursor and any client. Coming up: imports that do not exist and functions that duplicate another one in the repo.

The ruff of Java

Checkstyle, PMD and SpotBugs, without a JVM and without compiling.

Python has ruff and JavaScript has Oxlint and Biome. Java is still stuck with three tools that each start a JVM, and SpotBugs forces you to compile before analyzing.

  • Today: complexity, length and parameters counted exactly like Checkstyle and PMD, without starting any JVM.
  • Coming up: every shape rule of Checkstyle and PMD, and SpotBugs' data-flow analysis on the source code (nulls, unclosed resources, swallowed exceptions) without going through bytecode.
  • Seconds instead of minutes in the gate, without fighting the build for memory.

Install

Try it on your repo in a minute.

On Linux and macOS, and on Windows from Git Bash, one command: it downloads the binary for your machine, verifies the sha256 and puts it in ~/.local/bin. Also with Homebrew, brew install mati-caliz/tap/kerbo, or with Rust, cargo install kerbo --locked. Messages follow your locale; --lang en or lang = "en" in kerbo.toml forces English.

curl -fsSL https://kerbo.matiascaliz.com.ar/install.sh | sh
kerbo check --lang en
